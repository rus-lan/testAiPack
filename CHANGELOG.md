Все заметные изменения проекта фиксируются в этом файле.

## [0.4.0]

### Added

- `--model <provider/model>` — модель для обеих сторон прогона. Запекается в
  оба сгенерированных opencode-конфига (baseline и new — одинаково).
  Приоритет: `--model` (CLI) > `model` в `.testaipack/config.json` > модель
  из реального `~/.config/opencode/opencode.json` пользователя. Если не
  задан — поведение не меняется.
- Ограниченный retry с экспоненциальным backoff вокруг `opencode export`,
  когда он возвращает усечённый/невалидный JSON (до 3 попыток, база 200ms,
  потолок 3s) — сразу после завершения прогона сессия иногда ещё дописывается
  на диск.
- Изоляция HOME (фаза 04) переносит из реального
  `~/.config/opencode/opencode.json` в оба изолированных HOME (baseline и
  new, одинаково) поля `provider`, `small_model`, `enabled_providers` и
  `disabled_providers` — без этого кастомный провайдер (например, локальный
  сервер модели) был не виден внутри изоляции, и прогон на локальной модели
  падал с «unknown provider».

### Changed

- Preflight (auth-ping, gate 2 и его повтор в gate 5) теперь пингует именно
  ту модель, которую будет использовать сам прогон (`--model`, либо
  ambient-модель из сгенерированного конфига, если `--model` не задан) —
  раньше пинговалась `--preflight-model`, из-за чего preflight мог пройти на
  дешёвой здоровой модели, пока сам прогон падал на другой.
- `--preflight-model` теперь выбирает только модель LLM-судьи (фаза 09);
  auth-ping её больше не читает.
- `renderJson` / `renderYaml` возвращают `Effect` вместо исключения —
  провал валидации схемы отчёта теперь корректный `PhaseError`
  (`E_EXPORT_INVALID`), а не необработанный defect.
- `MetricDelta.percent` теперь опционален; переход 0 → N рендерится как
  «n/a» вместо обманчивого «0.0%».

### Removed

- `fileDiffStats` из `SecondaryMetrics` — убран из контракта и
  сгенерированных типов, а не починен: поле читалось из summary самого
  экспорта opencode, который всегда возвращает нули, а фаза 07 выполняется
  раньше фазы 08, так что структурно не могло увидеть реальные diff-числа.
  Реальные суммарные +/-/файлы по каждой стороне теперь показывает
  `report.md` (из данных diff-фазы). Старые `report.json` с этим полем
  по-прежнему успешно загружаются — Zod по умолчанию отбрасывает
  неизвестные ключи.

### Fixed

- `--ephemeral` / `--config` / `--ide` / `--review-run` были нерабочими и
  обрывали прогон.
- `--model` / `--preflight-model` отклоняли ссылки вида `provider/model:tag`
  — стандартная нотация ollama (`ollama/qwen3.5:9b`, `ollama/llama3.1:8b`).
  Валидатор теперь принимает `provider/model`, `provider/model:tag` и
  `provider:model`.
- Обнаружение rate-limit ложно срабатывало на случайное вхождение «429» в
  теле tool-вызова — здоровый прогон незаметно выпадал из сравнения.
- `dbQuery` передавал несуществующую подкоманду `query` opencode CLI —
  каждый запрос к дереву сессий падал, и таймлайн незаметно откатывался к
  «только корень» без явной ошибки.
- `--collapse-repeats` схлопывал `tool-result` вместе с соседним
  `tool-call`, включая маркеры ошибок.
- git-подпроцессы не завершались по таймауту и продолжали работать в фоне.
- Таймауты spawn-процессов никогда не эскалировались дальше SIGTERM —
  процесс, игнорирующий SIGTERM, оставался жив.
- Preflight gate 4 (pack-visibility) проверял исходную директорию пакета
  вместо реального «нового» HOME — сломанная регистрация пакета проходила
  gate незамеченной.
- Значения `--prompt`/`--init`/`--verify`/`--judge`, начинающиеся с `-`,
  ошибочно отклонялись как «флагу нужно значение».
- Отрицательные таймауты (`--timeout-*`) принимались без ошибки.
- `--auth <неизвестный kind>` молча игнорировался вместо ошибки парсинга.
- `init --workspace foo` писал в `.gitignore` строку `.testaipack/`
  независимо от реального имени рабочей директории.
- Экранирование имени tool-а при рендере HTML-класса в таймлайне.
- `stdoutFormat` фактически был константой — одна из веток была
  недостижима.
- Несколько мёртвых веток кода в фазах 05/09/10/11.

### Security

- Pack ref, чьё имя резолвилось в `..`, приводил к рекурсивному удалению
  корня рабочего дерева прогона.
- LLM-судья запускал write-enabled агент `build` с `--auto` в реальном
  `$HOME` пользователя, получая в промпт непроверенный diff-контент
  агента под тестом — теперь read-only агент `plan`, `auto: false`,
  отдельная scratch-директория; учётные данные для модели по-прежнему
  берутся из реального `$HOME`.
- Session id валидируется перед интерполяцией в SQL-запрос дерева сессий.
- Inline `mcp:`-pack-ref (несущий API-ключи в `env`-блоке конфига) и
  credentials, встроенные в clone URL, редактируются из сообщений об
  ошибках и контекста ошибок.

## [0.3.4]

- `execCmd` не передавал `encoding: 'utf8'` в `execFile` — вывод
  `opencode export` приходил как `Buffer` вместо строки.

## [0.3.3]

- Краш `opencode run`: реальный session ID теперь извлекается из потока
  событий для export (раньше при ненулевом exit code откатывался на
  фейковый ID).

## [0.3.2]

- `OpencodeError` захватывает `stdout` вместе с `stderr` — устраняет
  потерю ошибки, когда opencode пишет диагностику в stdout как JSON.
- `failOnNonZero` сохраняет `stdout` в контексте ошибки (было
  захардкожено `''`).
- `exportSession` обнаруживает пустой `stdout` и падает с описательным
  сообщением, включающим session ID.
- Контекст ошибки экспорта в фазе 06 теперь включает `exitCode` +
  `stdout` для диагностики.
- Preflight `stderrOf()` откатывается на `stdout`, если `stderr` пуст.
- Regex обнаружения отсутствия auth ужесточён — убраны ложные
  срабатывания на «no provider».

## [0.3.1]

- Флаг `--version` / `-v` в CLI (проверка после установки в `install.sh`
  падала без него).
- pack-detector: git-URL без суффикса `.git` теперь принимаются
  (`https://github.com/owner/repo`, `git+https://...`, SCP
  `git@...:owner/repo`).
- pack-detector: префикс `git+` убирается перед клонированием
  (npm-конвенция; сам git его как remote helper не понимает).
- pack-install: `SKILL.md` резолвится без учёта регистра (пакет graphify
  использует `graphify/skill.md`, opencode сканирует только заглавный
  `**/SKILL.md`).
- Реальный e2e прогон проверен на живом пакете graphify skill.
